SBOM 통합 가이드: 소스코드 vs 도커 이미지

백엔드 및 프론트엔드 컴포넌트 스캔의 차이점과 배포 수명 주기에 따른 보안 전략 가이드

☕ 1. 백엔드 (Spring Boot) SBOM 비교

백엔드 서비스의 자바 라이브러리 선언 영역과 실제 컨테이너 패키징 런타임 간의 구성 비교입니다.

📝 소스코드 SBOM (backend-build-sbom)
  • 스캔 기준: Gradle 빌드 설정 파일 (build.gradle)
  • 추출 범위: 개발 시점에 사용하겠다고 선언한 3rd-party 라이브러리 관계망
  • 주요 컴포넌트: Spring Boot core, Jackson parser, Lombok 등 Java 패키지
  • 보안 초점: 소스코드 작성 단계에서 사용하는 라이브러리의 알려진 취약점 점검
🐋 도커 이미지 SBOM (backend-image-sbom)
  • 스캔 기준: 최종 빌드된 백엔드 도커 이미지 전체 파일 시스템
  • 추출 범위: OS 패키지 + WAS 엔진 + JDK 런타임 + 최종 확정된 Java 라이브러리
  • 주요 컴포넌트: Ubuntu OS 패키지(OpenSSL, glibc), Tomcat, Java 17, JAR 파일 내부 라이브러리
  • 보안 초점: 해커의 타겟이 되는 컨테이너OS 취약점 및 미들웨어 위협 종합 대응

⚛️ 2. 프론트엔드 (React) SBOM 비교

프론트엔드 자바스크립트 패키지 영역과 실제 웹서버를 동반한 컨테이너 배포 환경 간의 구성 비교입니다.

📝 소스코드 SBOM (frontend-build-sbom)
  • 스캔 기준: Node.js 패키지 잠금 파일 (package-lock.json)
  • 추출 범위: 브라우저 실행 및 번들 빌드를 위한 자바스크립트 모듈 목록
  • 주요 컴포넌트: React, Axios, Webpack/Vite, Babel, Emotion 등 NPM 라이브러리
  • 보안 초점: 클라이언트 단의 종속성 취약점(XSS 유발 가능 라이브러리 등) 방어
🐋 도커 이미지 SBOM (frontend-image-sbom)
  • 스캔 기준: 최종 정적 배포용 Nginx 웹 서버 도커 이미지 파일 시스템
  • 추출 범위: OS 패키지 + Nginx 엔진 + 컴파일된 정적 자산(JS/CSS/HTML)
  • 주요 컴포넌트: Alpine Linux OS 패키지, Nginx 웹 서버 소프트웨어, 번들링 완료된 React 자산
  • 보안 초점: 웹 서버 자체의 보안 패치 및 컨테이너 내부 환경 위협 최종 점검

📊 3. 소스코드 SBOM vs 도커 이미지 SBOM 핵심 요약표

구분 소스코드 SBOM (Build-SBOM) 바이너리/도커 이미지 SBOM (Image-SBOM)
스캔 시점 소스코드 컴파일 및 빌드 전 (개발 단계) 도커 빌드 완료 후 및 실서버 배포 직전 (배포 단계)
분석 대상 의존성 선언 파일 (build.gradle, package.json 등) 도커 이미지 전체 디스크 영역 및 OS 파일들
백엔드 구성 Java 라이브러리 (Spring Boot 모듈) OS(Ubuntu) + JDK + Tomcat + 최종 .jar 내부 Java 라이브러리
프론트엔드 구성 자바스크립트 패키지 (NPM 라이브러) OS(Alpine) + Nginx 웹서버 + 빌드된 React 정적 자산
보안 스캔 범위 라이브러리 레벨의 정적 코드 취약점 위주 탐지 운영체제(OS) + 미들웨어(WAS) + 라이브러리 통합 탐지
용량 및 크기 상대적으로 매우 작고 가벼움 인프라 패키지를 대량 포함하므로 매우 크고 무거움

💡 4. DevSecOps 관점에서의 실무 시사점

🛡️ 오탐(False Positive)의 인프라성 원인과 VEX의 중요성

파이프라인 구축 후 5단계(Docker 이미지 스캔)에서 대량의 고위험 취약점이 검출되어 빌드가 실패하는 이유는, 개발자가 작성한 소스코드나 직접 주입한 라이브러리가 위험하기 때문이 아닙니다. 대부분 베이스 OS(Ubuntu/Alpine)의 노후 패키지나 Nginx/Tomcat 미들웨어 자체의 런타임 취약점이 원인입니다.

이러한 인프라성 위협들은 단시간에 해결하기 어렵거나 실제 서비스 구동 방식상 무해한 경우가 많습니다. 따라서 보안 차단 옵션(--fail-on high)을 켜둔 상태로 빌드 시스템을 유연하게 운영하기 위해서는, 안전성이 확보된 항목을 걸러주는 VEX(Vulnerability Exploitability eXchange) 예외 처리 연동이 필수적입니다.
